# 待确认

11 条产品决策已拍板（2026-09-01）；P0–P3 实现与自动化完成。改范围须先改本表和 PRD，再写代码。真实 Feishu/Lark、launchd 与模型调用属于待验证证据，不是新的产品决策。

## 必须拍板

1. **包名**是否确定为 `@kedoupi/pi-im-feishu`？（目录将是 `packages/pi-im-feishu`）
2. **绑定方式 v1** 做哪种：只填 App ID + Secret，还是必须有扫码开通？
3. **P1 没有飞书 SDK 时**：启动失败并显示离线（设计建议），还是允许「在线但收不到消息」？
4. **P0 是否要真连飞书**，还是 P0 只做本机在线（锁 + 进程），P1 再连 WS？
5. **窗口贴上**：v1 只检查+说明（建议），还是第一期就要 `switchSession`？
6. **群 all 模式**：v1 做不做？做的话控制台权限只写文档，还是产品里做引导？
7. **开机自启**：v1 明确不做（建议，与 ax 现状一致），还是必须做 macOS launchd？
8. **第一期语言**：TUI 与飞书回复中文为主、英文为辅，还是跟 Pi 界面语言走？
9. **与 ax-feishu-bridge**：只文档互斥，还是检测到同一 appId 时拒绝启动？
10. **私聊谁可以说话**：v1 要不要白名单？
11. **后台工具审批**：全自动、飞书点确认、还是卡住等电脑？

## 已在调研中视为事实、可推翻

- 关窗口必须靠第二进程，不能只靠 extension 生命周期。
- 不默认 `process.cwd()` 当文件夹。
- 默认不对公网开 webhook。
- 不把 dsh-im 源码拷进本仓。
- 批准前不建包。
