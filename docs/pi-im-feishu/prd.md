# 产品需求：@kedoupi/pi-im-feishu

- 日期：2026-09-01
- 状态：已批准
- 包名：`@kedoupi/pi-im-feishu`
- 依据：[调研](./research.md)
- 配套：[技术方案](./technical.md) · [实施计划](./plan.md) · [待确认](./open-questions.md)

已批准。本文是用户可见行为的合同。实现以本文与技术方案为准。

## 1. 一句话

这台电脑绑一次飞书。人可以离开屏幕用飞书干活；回到电脑只看在线、看清单、把窗口贴到某条对话上。

## 2. 给用户的三个角色

| 名字 | 干什么 | 能不能关 |
| --- | --- | --- |
| 飞书助手 | 连飞书、干活、养对话 | 电脑开着就应一直在 |
| Pi 窗口 | 接入、看在线、切到某条对话 | 随时关 |
| 对话 | 某个飞书聊天对应的工作记录 | 关窗口也不丢 |

用户只认识：**在线**、**离线**、**当前对话**。不说 Host、daemon、extension、session 文件。

合盖 / 关机 / 没网：飞书也叫不动。说明书写清「人可以离开屏幕，机器不能离开电源和网络」。

## 3. 决策（批准即锁定）

1. 电脑是中心，不是项目。飞书整机绑一次。
2. 分支是飞书聊天（私聊 / 群 / 话题），各养各的文件夹和对话。
3. 飞书换工作，电脑换视角。两面互不替代。
4. 关窗口 ≠ 离线。只有用户说停，助手才停。
5. **在线 = 飞书能收到，并且本机助手进程在。** 只活着收不到消息，不得显示在线。
6. 没选绝对路径文件夹不准干活。不默认当前目录。
7. **v1 群里只有 @ 才回。** 不做 all 入口。
8. v1 私聊不做白名单；能私聊这只机器人即可说话。以后再加限制。
9. 只读工作与工作区内新建文件可自动执行；覆盖现有文件、非明确只读命令、越界/网络/服务等重要操作由原请求者在同一飞书聊天确认，不等电脑窗口。
10. **v1 绑定两条路都要：扫码开通，或手动填写 App ID + Secret。** 绑的是同一只整机机器人。
11. 飞书 SDK 随包装上，用户不用自己装。
12. **v1 电脑登录后助手应自启**；用户停过则保持离线，开机不得擅自再上线。
13. 飞书文案中文为主；TUI 能跟 Pi 语言就跟。
14. 第一包只做飞书。不抽空内核，不做 Suite，不加第二渠道。
15. 常驻助手是干活的人，不是空壳守门进程。

## 4. 交互

### 4.1 飞书面

| 动作 | 感觉 |
| --- | --- |
| 打开另一个私聊 / 群 / 话题 | 换了一条工作，互不串 |
| 这条里「新对话」 | 还是这个人，换一件新任务 |
| 这条里「换文件夹」 | 还是这个人，改去另一份代码 |
| 这条里「以前的」 | 还是这个人，接上某次草稿 |

当前飞书窗口 = 当前工作。没有总开关叫「当前 session」。

### 4.2 电脑面（TUI）

| 动作 | 感觉 |
| --- | --- |
| 接入（扫码或填写） | 这台电脑绑上飞书 |
| 看在线 / 离线 | 飞书能不能收到，助手还在不在 |
| 看清单 | 飞书上正在养哪些工作 |
| 点其中一条 | 窗口要不要贴到那条上 |
| 停 | 飞书先别干活了 |

TUI 不帮用户在飞书里换群。飞书跟周会聊、电脑贴着张三看，可以同时成立。

P3 已实现贴上：文件夹和现有 session 文件匹配后，助手进程先释放所有权，Pi 窗口再 `switchSession`；窗口持有期间飞书侧暂停写入，匹配窗口关闭后助手可接回。无文件夹、尚无对话或目录不一致时只给人话说明，不 silent 切目录。

## 5. 用户故事

1. 我可以扫码开通，也可以手动填 App ID 和 Secret。两种方式绑完都看到「飞书在线」——此时飞书已能收到消息，本机助手也在。
2. 我关掉 Pi，手机飞书私聊仍能发到本机（P0 起就能收到；P1 起才干活改代码）。
3. 群里不 @ 它不理；@ 了才回。
4. 某条聊天第一次说话，它先问文件夹；选完之前不改我磁盘上的文件。
5. 我回到电脑，清单里能认出张三、周会、某话题。
6. 我点停，飞书没人接，没有残留进程抢连接。

## 6. 范围

### 做

- 一台电脑一只飞书机器人
- 接入：扫码开通，或手动填写 App ID + Secret
- 助手常驻；窗口可关；在线时飞书收得到
- 电脑登录后自启；停过保持离线
- 飞书 SDK 随包装上
- v1 私聊无白名单；群要 @；重要操作飞书确认，其余全自动
- 每个飞书聊天一条工作线
- 飞书里对话、停止、换工作
- 电脑上看状态、停止、绑文件夹、文件夹一致时贴上
- 凭据不进 git / tarball / 状态文案
- 默认不对公网开端口

### 不做

- 九渠道、多机器人界面、企微办公、AI Office
- 再做一套 Harness / Web Hub
- 群 all（不 @ 也回）、私聊白名单、真跟随终端对话
- 绝对安全承诺
- 把 dsh-im 源码拷进本仓
- 文档未批准就建包；dogfood 未完成且维护者未确认就加 publish workflow / Suite / 开发 Skill

## 7. 功能需求

**FR-01 整机绑定**  
这台电脑只绑一只飞书机器人。v1 必须同时支持（交互对齐 ax-feishu-bridge / dsh-im，文案用本包产品词）：

- **扫码开通**：用户先选扫码。Pi 窗口出码（可附链接）。用飞书或 Lark 扫码，由开放平台创建/授权应用。码过期、用户取消、租户从飞书切到 Lark（或相反）须有人话说明。成功后凭据写入本机（config 无明文 Secret，Secret 进 `0600` 文件），域名按租户品牌自动落成飞书或 Lark。
- **手动填写**：用户选已有应用，输入 App ID、App Secret，以及飞书或 Lark 域名。写入同一份绑定后须能验明应用可用（验失败不得显示在线）。

两条路更新的是同一份绑定，不创建第二只机器人。重复接入覆盖这一份。扫码失败、过期、拒绝须能改走手动填写，不得卡死。print/JSON 模式不弹码，只接受手动填写或提示去 TUI。

**FR-02 在线与离线**  
「在线」同时满足：本机助手进程在、飞书长连接已接通、飞书侧能把消息送到这台电脑。窗口「开始」保持在线，「停止」离线并释放连接。关 Pi 窗口不改变在线。进程在但连不上飞书：显示离线或启动中，不得显示在线。无飞书 SDK：不得显示在线。

**FR-03 状态词**  
未绑定 / 在线 / 离线 / 启动中。主文案不出现 pid、锁路径、RPC。可附打码 App ID。

**FR-04 聊天清单**  
每条出现过的飞书工作：标题、私聊或群或话题、文件夹或「未选择」、最近活动。来自助手路由表，不是当前终端会话。

**FR-05 文件夹**  
必须是绝对路径。未选择时只告诉怎么选，不建对话、不跑工具。电脑和飞书两侧都能绑。

**FR-06 群策略**  
v1 只有 mention：群里未 @ 本机器人则忽略。不做 all 开关。忽略机器人自己的消息。控制台「获取群聊全部消息」只作为以后文档，不进 v1 产品。

**FR-07 入站分流**  
私聊、群、话题（thread）各一条工作，上下文不串。

**FR-08 飞书干活**  
已绑文件夹：文本进入该聊天的 Pi 对话，回复回同一聊天。同一聊天串行。进行中可停。普通工具自动执行。重要操作（FR-15）须在飞书里确认后才继续。

**FR-09 飞书换工作**  
同一聊天：新对话（旧草稿保留）、换文件夹、列出并接上以前的。对用户不叫 session。

**FR-10 窗口贴上**  
P3 已实现跨进程所有权交接。仅当当前 cwd、已绑定文件夹和已有 Pi session 文件匹配时请求窗口 lease；助手中止/排空该聊天、持久化并释放后，窗口才 `switchSession`。窗口持有时飞书消息不写同一 session；匹配窗口 shutdown 后释放。失败与超时不切 session。

**FR-11 远程控制披露**  
安装说明必须写：能私聊或在允许的群里 @ 这只机器人的人，等于在远程使唤这台电脑上的 coding agent。v1 私聊没有白名单。

**FR-12 飞书说明**  
接入成功有欢迎说明；之后能再看帮助。没有图形菜单时，电脑侧命令仍须能绑文件夹。

**FR-13 文件**  
入站文件进入 `<bound-folder>/.pi-im-feishu/inbox/<message-id>/<safe-name>`，使用排他创建和后缀避免覆盖；下载失败则本轮失败。出站只能由 `send_feishu_file` 排队工作区内普通文件，经原请求者确认后发回当前来源聊天/话题。自动化只使用注入 API，真实上传下载待一次性应用验收。

**FR-14 连接独占**  
同一飞书应用同一时间一个长连接。本包用自己的锁，不读 ax-feishu-bridge 的锁文件。README 写明不要两包抢同一应用。WS 因占用失败：显示离线，并提示可能被其它客户端占用。

**FR-16 开机自启**  
电脑登录后，若本机已绑定且用户上次不是「停止」，助手应自动起来并达到在线（飞书能收到）。用户执行停止后，重启电脑不得擅自再上线，直到用户再次开始。macOS 优先。失败时下次打开 Pi 能看到离线原因。合盖睡觉仍不保证在线。

**FR-15 重要操作飞书确认**  
无电脑窗口时也要能干活。只读工具、工作区内新建文件和保守只读 shell 命令可自动执行。下列操作必须先在**当前飞书聊天**给出可理解的说明，并由原请求者确认后才执行；群/话题还必须 @ 当前机器人。拒绝或超时则跳过该步并说明，不得在 TUI 里干等：

- 删除文件或目录
- 覆盖已有文件（用户未在本轮明确要求写该路径时）
- 执行带破坏性的系统命令（例如删文件、改权限、装全局包）
- 把本机文件发到飞书以外
- 其他实现时列入清单、并写进 README 的操作

清单在实现前可收紧，不可在未改本文的情况下变松。确认消息不得包含 secret。

| 片 | 用户能感到什么 | FR |

| P0 遥控器 + 真在线 | 扫码或手动填写后飞书能收到、本机进程在、关窗口仍能收到、登录后能自启、停得干净。可以还不跑模型、不改代码。 | 01–05, 11, 14, 16 |

## 10. 成功标准

1. 接入一次，看见在线；此时飞书私聊发一句，本机收得到（P0）。
2. 关掉 Pi，飞书私聊仍收得到（P0）；有文件夹后仍能干活（P1）。
3. 群不 @ 不理（P1）。
4. 回到电脑看见清单；文件夹不对时得到人话说明。
5. 停止后飞书没人接；停过再开机不会自己上线。
6. 登录电脑后（未停过）不必先开 Pi，飞书仍能收到（P0）。

工程门禁（包存在之后）：`npm run check`、`npm test`、`npm run pack:check`。发布另需维护者确认。

## 11. 文案原则

- 主词：在线、离线、对话、文件夹、清单。
- 飞书命令、帮助、确认以中文为主：「新对话」「换文件夹」「以前的」。
- 电脑命令可以是 `/feishu …`，帮助里用上面的词解释；TUI 能跟 Pi 语言就跟，跟不上就中文。
- 不要教用户「切 session」「起 daemon」。
